# CI / GitHub Actions 사용 정책

이 프로젝트는 GitHub-hosted Actions 사용량을 비용 자원으로 취급한다. 개발 중간 단계에서는 로컬 검증을 우선하고, 원격 CI는 결과를 확인할 가치가 있는 시점에만 실행한다.

## 기본 원칙

1. **중간 커밋마다 GitHub Actions를 실행하지 않는다.**
   - 문서, 주석, 사소한 정리, 작업 중간 저장 커밋에는 `[skip ci]`를 사용한다.
   - 여러 수정은 가능한 한 의미 있는 단위로 묶어 검증한다.

2. **로컬 검증이 먼저다.**

   ```bash
   npm test
   npm run build
   ```

   의존성 재설치가 필요한 경우에만 `npm ci`를 먼저 수행한다.

3. **원격 CI는 최종 검증용으로 사용한다.**
   - 기능 단위 구현이 끝났거나 GitHub runner 환경 확인이 필요할 때만 `[skip ci]` 없이 push한다.
   - 단순 UI 문구/문서/정리 변경으로 원격 CI를 소비하지 않는다.

4. **실패 workflow를 반복 재실행하지 않는다.**
   - 로그 분석 → 원인 수정 → 로컬 테스트/빌드 → 필요 시 원격 재검증 순서로 진행한다.
   - 실패 원인을 수정하지 않은 상태에서는 rerun하지 않는다.

5. **작은 변경을 묶어서 검증한다.**
   - 파일 하나 수정 → CI → 또 수정 → CI 식의 반복을 피한다.
   - 하나의 기능/버그 수정 단위를 마친 뒤 한 번에 검증한다.

## AI 작업 규칙

AI가 이 저장소를 수정할 때도 동일하게 적용한다.

- 작업 중간 커밋: 기본적으로 `[skip ci]`
- 코드 변경 없이 문서만 수정: `[skip ci]`
- 최종 의미 단위 커밋: 원격 검증 필요 시에만 CI 실행
- CI 재실행: 실패 원인을 수정한 뒤에만
- 먼저 `npm test` / `npm run build`로 로컬 검증

## 예외

Node 버전, dependency/lockfile, 빌드 설정, CI workflow, 배포 관련 변경처럼 원격 환경 차이가 중요한 경우에는 중간 단계라도 CI 실행을 허용한다.
